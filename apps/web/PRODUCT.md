# Shorts Studio product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users and purpose

Gameplay creators upload their original recordings and manage a reliable source library for a future AI-assisted Shorts workflow. The master specification and docs/architecture.md remain the architectural source of truth.

## Capabilities and constraints

Phases 1–8 include owner authentication, resumable source uploads, analysis/ranking, versioned EDLs, Remotion rendering and QC, editorial slate planning, secure YouTube connection, private resumable publication, scheduling, reconciliation, campaigns, immutable YouTube Analytics snapshots, estimated revenue, evidence-bound performance learning, versioned strategy recommendations, and controlled experiments. All states and metrics come from the API.

Phase 8 learning uses only the owner's persisted provider observations. Minimum samples, rolling windows, confidence labels, nullable unavailable horizons, bounded adjustments, and reversible audited strategy versions prevent thin data from becoming an unsupported claim. Existing routes and security boundaries remain intact.

## Brand commitments

One dashboard and one animated hero using the user's supplied Smartphone_AI_gaming_workflow video. Efferd hero-2 and dashboard-4 are style and compatible structure references, not replicas. The user approved direct code implementation and verification of real screens.

## Evidence on hand

The existing Phase 1 application, architecture and verification documentation, the user-supplied MP4, and live API responses. No customer endorsements, audience statistics, or published-video performance evidence has been supplied.

## Accessibility and principles

Preserve keyboard access, visible focus, descriptive errors, responsive layouts, readable contrast, and reduced-motion support. A decorative video must be muted and pausable. Keep the next real action easy to find, and distinguish future previews from available functions.

Learning, experiment, publication, analytics, revenue, edit, render/QC, and recording states originate from the API. Predicted performance is a ranking signal, never a promise.
